# MD-Axx 任务记录规则

## 编号与层级

- `MD-Axx` 表示一个大任务，描述完整目标、边界、依赖、共同验收和发布影响。
- `MD-Axx-yy` 表示该大任务下可独立交付的子项。子项必须写明所属大任务，不另起一套验收口径。
- 路线图使用 `MD-Axx` 跟踪大任务状态；子项完成、延期或阻塞时，同步更新大任务状态和依赖说明。

## 子项内容

每个子项至少记录目标、范围与非目标、实现变更、验收标准、验证命令和剩余现场验证。多个子项共享的协议、资产或测试门禁写在大任务记录中，子项只补充自己的行为断言。

## 完成与阻塞

子项只有在代码、兼容性、测试和文档均完成后才能标记完成；未运行的设备或现场验收不得写成已验证。测试受环境限制时，记录原始阻塞原因、已完成的替代验证和解除阻塞所需条件，不通过修改验收标准来规避门禁。

## 变更纪律

子项保持范围收敛，不覆盖其他未提交改动；涉及共享状态、协议或资源加载顺序时，必须同步更新对应的 Node、Android、网页测试和路线图说明。任务记录只描述实际变更，不承诺未实现的能力。

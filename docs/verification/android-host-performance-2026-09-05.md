# Android 手机宿主性能实测（2026-09-05）

归属 MD-A16，当前测试代码 `d3a7602`（包含 MD-A18），分支 `codex/md-a18-receiver-quick-controls`。本次只测试与记录，不修改运行时代码。

## 环境与方法

- 单台 `22127RK46C`，Android 16（WebView UA），Google WebView `149.0.7827.163`，USB 连接且充电；手机前台运行内置宿主控制页。
- Wi-Fi 宿主地址 `192.168.0.137:8765`。USB 对照使用 ADB 本机 `19865` 转发到手机 `8765`，不经过 Wi-Fi，但仍包含 USB/ADB 开销。
- 电脑上一个真实 Chromium 投放页；另用 Node HTTP/SSE 模拟 20 个接收会话。模拟会话持续读取 SSE，不模拟 Android 渲染、逐台 heartbeat 或全部交互，不能换算为 20 台手机容量认证。
- GET 使用单连接串行 50 次、并发 10 路共 200 次。推送使用串行 POST 更新 randomSeed，目标每秒 10 次，按序号统计所有 SSE 客户端到达时间；慢 POST 会降低实际频率。时间均包括客户端、传输和服务端处理。
- 推送正式测试期间，资源采样在异步子进程执行，不阻塞计时事件循环。初步探针曾错误地假设 SSE 块以 event 行开头（实际以 id 行开头），其零接收统计已废弃；下表使用修正后的完整正式数据。
- 原始 JSON、ADB 资源采样和截图位于本工作树 `output/adb/host-perf/`（本地忽略目录）。

## 实测结果

### 启动和普通控制

- 从点击“本机作为宿主”到 WebView 导航至 control URL，轮询观察约 121 ms；本地控制页面导航 loadEventEnd 为 156.5 ms。这是单次观察，不是冷启动分位统计。
- 电脑经 Wi-Fi 加载真实投放页约 241.5 ms（navigation loadEventEnd）。
- 20 次交替锁定/解锁，全部收到 confirmed=1：DOM 状态生效并等待两个 requestAnimationFrame 的耗时 P50 34.4 ms、P95 92.2 ms、最大 140.4 ms；确认查询完成 P50 52.9 ms、P95 143.8 ms、最大 177.2 ms。不是光学拍摄得到的物理屏幕延迟。该测试与正式模拟负载部分重叠。

| 路径 | 更新数 | 收到/预期事件 | 实际阶段耗时 | SSE P50 ms | SSE P95 ms | SSE 最大 ms | POST P95 ms |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Wi-Fi | 600 | 12000/12000 | 73.38 s | 32.74 | 480.09 | 963.73 | 480.50 |
| ADB USB | 200 | 4000/4000 | 37.15 s | 57.83 | 485.11 | 529.10 | 499.68 |

两组均无请求错误、无所计事件丢失。串行发送未能持续达到目标 10 Hz；包含最后 0.5 秒排空的有效更新率约为 Wi-Fi 8.2 Hz、USB 5.4 Hz。

追加相同 USB、20 个 SSE 接收会话的对照，只将 POST 客户端改成 Node `http.request`、`agent:false`（每次新建连接，SSE 仍使用 fetch）：200 次更新在 20.45 秒完成，4000/4000 事件收到，SSE P50 29.32 ms、P95 47.23 ms、最大 68.75 ms；POST P95 43.75 ms、最大 49.64 ms。该对照保持目标 10 Hz（末尾包含 0.5 秒排空）。

因此先前约半秒的波动显著依赖请求连接方式/客户端与宿主的交互，不能归因于手机算力不足，也不能直接代表浏览器生产路径。尚未定位具体连接复用行为；真实浏览器锁定数据与合成压测分开报告。对照原始数据为 `newconn-results.json`。

### 资源和短时后台

- Wi-Fi 正式负载，宿主主进程 PSS 基线约 263 MiB，采样为 277–286 MiB，结束约 282 MiB。包括主进程原生/图形内存，不等于完整应用及独立 WebView renderer 的总内存；短测不能判定没有泄漏。
- 主进程 CPU 在两个负载采样窗口约 7.4%–26%（Android top 的单核 100% 口径）；空闲约 0%–1%。不把稀疏采样当作全程峰值。
- 按 Home 后 20 次 Wi-Fi info 请求全部成功；P50 149.9 ms，P95 416.2 ms。
- 熄屏后 20 次 Wi-Fi info 请求全部成功；P50 63.5 ms，P95 636.8 ms。两阶段每次请求间隔 0.5 秒，仅证明短时继续服务，未验证长时 Doze/OEM 杀后台。
- 当前应用 PID 的 AndroidRuntime:E / chromium:E 日志未发现条目。

## 结论与待办

手机作为宿主的启动、真实投放页连接、普通锁定闭环已通过。本次负载未显示主进程 CPU 或内存接近耗尽，连接复用合成测试出现延迟波动，新连接对照则保持 10 Hz；不能据此保证 20 台实机低延迟。

本次发现的手机宿主状态栏遮挡已在 v1.7.0 发布收尾修复。修复版同机复验：control 竖屏 WebView 的 screenY 为 138 像素，标题位于状态栏下方；横屏 914×372 CSS 无横向溢出；切回 local 后 screenY 恢复 0，411×914 CSS 沉浸式投放正常。截图位于 `output/adb/release170/`。

待测：多台物理投放设备、长时间负载与后台、温度/耗电、慢客户端背压、其他 OEM，以及上述延迟波动的根因。测试会话与临时 ADB 转发收尾清理，保留手机宿主运行以便用户检查。
